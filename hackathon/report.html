Where the cold start went

Both timelines come from the -v=9 log of one cold run each, drawn on the same time axis. On the old path the engine waits on seven parallel npm installs, then boots a node process per pack. On the new path the packs are downloaded, extracted and evaluated in about 70 ms.

Cold preview, seconds since process start

Old: npm installs took 50–87 s per pack, and 87.5 s of wall time with all 7 in parallel. New: download and extract took 30 ms for all 7 packs, and loading each pack in goja took 11–34 ms (compile is about 60% of that and scales with bundle size).

New path

In-process, one goja runtime per pack. Packs load on background goroutines; Analyze is a direct function call.

What gets shipped

Old bundles are 18–20 MB because rollup's external list only matches exact package names, so subpath imports like @pulumi/aws/rds pull gRPC and Node built-ins into the bundle. New bundles keep only the __pulumiType tokens each pack actually reads, which is 2.4–9 KB of stubs per pack. About 55% of what's left is remediation text and framework metadata.

The contract: a policy is a function

A pack is one plain script that sets a global descriptor. The host (the Go CLI today, anything that embeds a JS engine tomorrow) filters by resource type, resolves enforcement levels, applies config defaults and formats messages. The policy only looks at JSON and reports.

// PulumiPolicy.yaml → runtime: purejs, main: policies.js
globalThis.__pulumiPolicyPack = {
  abiVersion: 1, name: "cis-aws", version: "1.0.2",
  policies: [{
    name, description, enforcementLevel, severity, configSchema, framework, ...,
    kind: "resource" | "stack",
    resourceTypes: ["aws:ec2/instance:Instance"],   // host filters before calling
    validate(input, ctx) {                            // input: { type, name, urn, props, config }
      ctx.reportViolation("…");                       // or ctx.notApplicable("…")
    },
  }],
};

Existing TypeScript policies compile to this unchanged, with a 1-file shim in place of @pulumi/policy and type-token stubs in place of @pulumi/aws. New policies are written with definePolicy, which targets ABI v2 (Part 2 below). Types come from import type, so they're erased at build time:

import type * as aws from "@pulumi/aws";

export const ec2Imdsv2Required = definePolicy<aws.ec2.InstanceArgs, Config>({
  name: "ec2-imdsv2-required",
  description: "EC2 instances must use IMDSv2",
  severity: "high",
  resourceType: "aws:ec2/instance:Instance",
  validate({ resource: { name, inputs }, config }, ctx) {
    if (inputs.metadataOptions?.httpTokens === "required") ctx.reportPass();
    else ctx.reportViolation(`EC2 instance '${name}' must require IMDSv2 for metadata access.`);
  },
});

Where the added 6 MB goes (darwin/arm64)

From go tool nm -size on unstripped builds (≈6.3 MB of symbols, against 6.0 MB stripped), so treat the split as approximate. Go's function and type tables grow with any added code and stay even in stripped binaries.

In perspective

  • The old runtime needs node installed; node v22 on this Mac is a 109 MB binary.
  • For these 7 packs, the old runtime then installs 2.16 GB of node_modules into the policy cache.
  • The purejs analyzer itself, prelude included, is about 32 KB. Nearly all of the cost is the engine.

Easy win

  • A quarter of the cost (~1.5 MB) is golang.org/x/text/collate and its Unicode tables. goja links it unconditionally to implement String.prototype.localeCompare, which no policy in these packs calls.
  • A small goja patch or fork that swaps in a plain comparison would bring the added size to about 4.5 MB raw.

Found along the way

  • Silent empty publishes. For non-nodejs runtimes, pulumi policy publish builds the tarball with archive.TGZ, which applies every .gitignore up to /. Publishing from a gitignored build directory uploads a 57-byte empty tarball and reports success; the failure only shows up at install time. Fixed for purejs, but Python and other runtimes are still affected.
  • Lookbehind regexes cost about 40 ms. hitrust, iso-27001 and pci-dss spend ~41 ms analyzing 12 resources, against 1–2 ms for the other packs. They are the only packs whose no-hardcoded-secrets policy uses lookbehind, which forces goja onto the backtracking regexp2 engine.
  • Deleted version tags stay reserved. After deleting a pack version, the service still refuses to republish that tag, so the new packs were published as <version>-purejs.
  • Go build-tag trap. A file named *_js.go only builds for GOOS=js, which is why the new files are called analyzer_purejs*.
Part 2

Policies at preview, with identifiable unknowns

Policies should stop bad infrastructure before it exists, which means at preview. Today they can't when resources depend on each other: on a first preview every value that comes from another resource's output is unknown, and the policy gives up. We make unknown outputs identifiable. An output that doesn't exist yet is one opaque value, the same wherever it appears, so a policy can connect resources before they exist.

The idea

  1. When: policies run at preview, before anything is created. A mandatory violation fails the preview.
  2. Identifiable unknowns: an unknown output is one object, identical in the resource's own outputs and in every input the program set from it.
  3. Inputs and outputs, explicit: a policy sees both, never merged. It validates inputs, what the code wrote, and uses outputs to connect resources.

The program

const good = new aws.s3.Bucket("good");
new aws.s3.BucketPublicAccessBlock("pab", {
    bucket: good.id,  // unknown until the bucket exists
    blockPublicAcls: true,
});

What the policy sees on the first preview

good.outputs.id   → <output good.id>
pab.inputs.bucket → <output good.id>

pab.inputs.bucket === good.outputs.id   // true
pab.inputs.bucket.split(":")            // advisory:
                                        // reads an output

The policy

definePolicy({
    name: "s3-bucket-public-access-blocked",
    resourceType: "aws:s3/bucket:Bucket",  // once per bucket; no type = once per stack
    validate({ resource, resources }, ctx) {
        const pab = resources.find((r) => r.inputs.bucket === resource.outputs.id);
        if (pab) ctx.reportPass();
        else ctx.reportViolation("no public access block");
    },                                     // report nothing = not applicable
});

Known values are always real, so the same comparison holds once the bucket exists. Identifiable unknowns are strict: they support identity (===, Set, Map) and conversion to text for messages. Reading into one, whether by splitting, parsing, comparing numerically or concatenating it, is reported as an advisory instead of a guess.

Built from outputs

new aws.s3.BucketPolicy("goodPolicy", {
    bucket: good.id,
    policy: pulumi.jsonStringify({ Statement: [{
        Effect: "Deny", Principal: "*", Action: "s3:*",
        Resource: [good.arn,
                   pulumi.interpolate`${good.arn}/*`],
    }] }),
});

What the policy sees

const st = JSON.parse(p.inputs.policy).Statement[0];
st.Effect                          // "Deny"
st.Resource[0] === good.outputs.arn         // true
st.Resource[1] === `${good.outputs.arn}/*`  // true
p.inputs.policy.includes("Deny")   // advisory:
                                   // reads an output

interpolate, concat and jsonStringify tell the policy how they built the string, so its known parts are real and its unknown parts are identifiable. A value made with apply runs arbitrary code, so it can't be known during preview.

What it took

  • Node.js SDK: tags each resource output with its resource and property, and says which output each unknown input is, or how interpolate, concat or jsonStringify built it.
  • Engine: keeps that information past registration and gives policies the inputs, outputs and ID. No proto, event or state change.
  • Host: builds inputs/outputs with identifiable unknowns, with no provider schema and nothing specific to a type or field.
  • Policies: compiled unchanged. A shim maps legacy props explicitly and reports the pass when an existing policy returns cleanly. The only source change: 11 S3 policies now also look a companion up by the bucket's id, one line each.

Not covered at preview

  • SDKs other than Node.js until they report output sources: their unknown inputs can't be identified.
  • The 6 policies that need real output values, such as an access key's creation date or an API's execution ARN.
  • Values made with apply: the callback is arbitrary code, so the result can't run at preview.
  • === "literal" on an unknown is silently false; everything else is caught.

Gaps and next steps

Not covered yet

  • aws-organizations-tag-policies makes async AWS SDK calls. Supporting it needs a host-provided data source.
  • hitrust-awsnative and cis-kubernetes-aws need their own stub sets.
  • Remediation policies (none in these packs).
  • The server-side Insights and TFE evaluators need a pulumi/pkg bump to run purejs packs.
  • No sandbox limits yet beyond call-stack depth; a per-call timeout would be cheap to add with Interrupt.

Worth doing next

  • Rewrite or precompile the lookbehind regexes (−40 ms per affected pack).
  • Patch goja to drop x/text/collate (−1.5 MB of the 6 MB CLI cost).
  • Emit a static manifest.json next to the bundle, so the service can list policies without running JS.
  • Build purejs into the release pipeline for policy-packs-internal and republish.
  • Make publish fail loudly on an empty tarball for every runtime.
  • Report output sources and templates from the Python, Go and YAML SDKs. As a fallback for SDKs that don't, the engine could hand the program placeholder id/arn values at preview.
  • Codemod shared policies onto definePolicy, so they report passes themselves instead of through the shim.

Method

  • The bench stack is a Pulumi YAML program with 11 AWS resources (S3 plus public-access-block, an open security group, an IAM role with a wildcard inline policy, EC2 with secrets in user data, public RDS, SQS, KMS, a log group). Previews run offline with fake credentials and the provider's skip-validation flags, so only policy handling varies.
  • Both modes use the same dev-built CLI. The old packs are published as old-<name> (nodejs) and the new ones under their original names (purejs), in two policy groups on a local Pulumi Cloud, one stack per group.
  • Part 2: hackathon/bench-linked-js is a Node.js program with 40 resources, run with the SDK reporting output sources; “Today” is the same program with the v1 packs. BENCH_BAD_POLICY=1 swaps its bucket policy for a public grant. bench-linked is the same program in YAML (35 resources). Both run through scripts/linked.py. The code is on policy-packs-internal branch hackathon-input-policies, with the pulumi changes as patches.
  • Raw data: hackathon/results/ in the pulumi repo (one JSON record, event log and stderr per run). Harness: hackathon/scripts/bench.py, parity.py, report.py; CLI size: cli-size.sh, cli-size-breakdown.py.
